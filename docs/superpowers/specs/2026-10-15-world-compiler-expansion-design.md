# 世界编译局扩展设计：三语平台、色觉模拟与完整工具目录

## 目标

将世界编译局从一个包含工具目录首页和色觉工具的站点，扩展为中英德三语公益工具平台：独立介绍首页、独立工具目录页、改进后的色觉模拟，以及让目录中其余三个工具都达到可用状态。所有工具继续在浏览器本地处理输入，不要求账户，不上传用户内容。

## 用户与成功标准

平台面向公众、设计与内容工作者，以及希望理解工具隐私边界的访客。成功意味着：访客能在三语间切换；首页讲清使命、隐私设计和许可；目录可搜索、分类并打开独立工具页；四个现有工具条目全部可运行；键盘、移动布局和本地数据边界保持可验证。

## 信息架构与语言

- `/` 是独立介绍首页，展示平台使命、本地优先隐私承诺、开源许可/版权信息，以及通往工具目录的清晰入口；不在首页内嵌目录卡片。
- `/tools/` 是独立工具目录页，提供搜索、分类过滤和紧凑卡片；每张可用工具卡通过普通链接打开独立工具页面。
- 工具使用独立页面：`/tools/color-vision/`、`/tools/contrast-lens/`、`/tools/plain-language/`、`/tools/data-shape/`。全站导航的“工具目录”指向 `/tools/`。
- 全站语言为简体中文、英文、德文。语言控件是原生、可访问的下拉选择；切换立即更新当前页面文案与页面元信息，并通过现有本地偏好机制记住选择。默认按浏览器语言回退为三者之一，未知语言回退中文。三种语言覆盖首页、导航、目录、全部工具、错误和状态提示。
- 工具目录卡片比当前样式紧凑，但仍保留标题、简短说明、分类/状态和清晰的打开链接。

## 色觉实验室

- 继续本地导入、预览、模拟、导出，不引入上传路径。
- 提供正常视觉、红色轴（protan）、绿色轴（deutan）、蓝黄色轴（tritan）、全色盲（achromatopsia）和蓝锥单色视（blue-cone monochromacy）的教育性模拟入口。红/绿/蓝三类提供从 0% 到 100% 的“模拟强度”滑杆：0% 为原图；100% 为相应二色视觉近似。标签准确区分异常三色视觉（-anomaly / 色弱）和二色视觉（-opia / 色盲），而不把滑杆数值描述成用户的临床程度。
- 原图与当前选择模拟结果并列比较；强度变化在浏览器 Worker 中实时处理。导出采用当前模拟类型与强度，导出仍保留原始像素尺寸、PNG/JPEG 选项及本地下载。
- protan/deutan/tritan 采用 Machado、Oliveira 与 Fernandes（2009）基于生理的严重度矩阵模型；按 0–100% 连续控制并在论文公布的离散矩阵锚点间插值。全色盲与蓝锥单色视作为单独的教育性近似模式，不冒充上述模型的临床重现。蓝锥单色视模拟仅描述颜色通道近似，不模拟视力下降、畏光、眼震等伴随表现。
- 页面明确说明所有模式是显示器相关的近似、不能诊断或准确代表某个个体；不同设备显示和个人体验会有差异。

## 其余工具的首版范围

### 对比度透镜 / Contrast Lens

- 用户用颜色选择器及十六进制文本输入前景色、背景色；输入实时校验并更新预览。
- 在浏览器本地按 WCAG 相对亮度公式计算对比度比例，显示普通文本与大号文本的 AA/AAA 结果。无网络依赖；错误颜色值不能进入计算。
- 公式与结果有简短说明，不将单次比例检查描述成完整无障碍认证。

### 清晰语言仪 / Plain Language Meter

- 用户粘贴文本后在本地分析，不保存、不发送。
- 提供独立于界面语言的分析语言选择（中文、英文、德文），默认跟随当前界面语言。所有语言都显示词/字数、句数、平均句长和长句提示；英文按 Flesch Reading Ease 公式、德文按 Flesch 德语公式给出基于近似音节计数的估算，中文不套用英语公式、不显示伪精确分数。
- 英文公式为 `206.835 - 1.015 × 平均每句词数 - 84.6 × 平均每词音节数`；德文公式为 `180 - 平均每句词数 - 58.5 × 平均每词音节数`。音节计数是本地拼写启发式，因此仅显示估算和方法说明，不声称精确的可读性等级。
- 输出明确标注为写作提示而非语言质量、理解能力或法律合规判定；空文本和极短文本不生成误导性的分数。

### 数据塑形台 / Data Shaper

- 支持本地 CSV/TSV 导入、预览、清理单元格首尾空白、移除完全空白行，以及下载整理后的 CSV。
- 正确处理引号、转义引号和分隔符；拒绝不支持/损坏的输入并给出可翻译错误。限制单文件最大 10 MB，避免过大文件占用浏览器内存。
- 原始文件不上传；用户可在导出前检查整理预览。第一版不包含云端存储、公式执行、表格转换以外的复杂数据操作。

## 技术结构

- 延续 Astro 静态输出、TypeScript 浏览器交互、Web Worker 处理像素、Vitest 与 Playwright 测试，不增加前端框架。
- 保持每个工具的纯计算逻辑在 `src/features/<tool>/`，界面在现有 Astro 工具组件/页面，三语文案收敛于有类型约束的 i18n 字典；目录数据仍以 `src/data/tools.ts` 为唯一来源。
- 新增工具页面由独立路由和轻量控制器初始化；首页与目录通过站点导航互链。GitHub Pages base path `/world-compiler` 下的页面、脚本、Worker 与下载流程都必须正常。

## 无障碍、隐私与错误处理

- 下拉框、强度滑杆、颜色输入、文件输入及所有操作可键盘使用，具有本地化可访问名称、可见焦点、状态播报和足够触控尺寸；尊重减少动态效果偏好。
- 所有输入在进入计算前校验；失败时显示对应语言错误并允许修复/重试。文件解析与模拟均在本机运行，除静态站点资源外不发送用户输入。
- 页面声明隐私边界不超出实际实现；保留 MIT 许可信息。

## 验收与测试

- Vitest 覆盖三语回退/持久化、色觉矩阵与强度端点/插值、对比度公式边界、可读性短文本与中德英分流、CSV 引号/换行/分隔符/非法数据/大小限制和清理导出。
- Playwright 覆盖独立首页与目录路由、目录筛选和工具导航、三语下拉切换及刷新持久化、色觉滑杆与导出、三个工具的主要流程、键盘操作、移动端无横向溢出，以及本地处理边界。
- 合并前运行 `npm run verify`；使用部署配置中的 `PUBLIC_BASE_PATH=/world-compiler` 和 `PUBLIC_SITE_URL=https://jiehua1995.github.io` 验证静态构建和浏览器测试。
